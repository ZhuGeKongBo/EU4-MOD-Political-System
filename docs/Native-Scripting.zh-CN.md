# 政治体系的原版脚本接入

这次接入针对 Windows Steam 版 EU4 1.37.5。自定义体系继续使用独立的实例、行动记录和存档。原版脚本块则交给游戏的读取器和执行器处理。

## 所有接口的开发规则

框架调用游戏脚本与游戏脚本调用框架使用同一份政治状态。新增或修改任何 trigger、effect、modifier 或 scope 时，同时说明可用位置、作用域、运行时机和失败行为。新增合法原版语句、作者自己的 scripted trigger 或 scripted effect 时，由游戏读入，通常只改 Mod 文件。原版专属的 `is_emperor`、`is_emperor_of_china` 等继续作用于原版体系。自定义体系通过 `political_*` 或 `ps_*` 选定实例。

## 哪里可以写原版块

| 位置 | 块可使用的对象 |
| --- | --- |
| 面板查看与入口显示、可用性 | `ROOT` 是玩家当前国家，`FROM` 是存在的实例领袖 |
| 成员来源、加入、退出和保留 | `ROOT` 是正在判断的国家，`FROM` 是存在的实例领袖 |
| 职位与领袖资格 | `ROOT` 是待判断的国家，`FROM` 是存在的实例领袖 |
| 提名评分 | 选民条件以选民为 `ROOT`、候选人为 `FROM`。候选条件反过来 |
| 实例成立与维持 | 成立以发起者为 `ROOT`、脚本指定的拟任领袖为 `FROM`。维持以当前领袖为 `ROOT`，空缺时用存在的建立者 |
| 防御义务 | `ROOT` 是被攻击的成员，`FROM` 是攻击方 |
| 资源月变 | 各国资源用对应国家。联盟共用资源可写 `political_leader = { ... }` 指定按领袖国家判断 |
| 行动 `potential`、`trigger`、`actor_trigger`、`ai_will_do` | `ROOT` 是发起国，指定目标时 `FROM` 是目标国 |
| 行动 `target_trigger` | `ROOT` 是目标国，`FROM` 是发起国 |
| 普通行动效果 | `ROOT` 按 `beneficiaries` 选择。目标或发起者按行动方向提供 `FROM` |
| 邀请接受效果 | `ROOT` 是受邀并加入的国家，`FROM` 是邀请国。先登记成员，再执行效果 |
| 事变开始、终止、选项 | 开始效果按发起国执行。终止与选项按现任领袖判断或执行，`FROM` 是原发起国 |

可继续嵌套 `capital_scope`、`owner`、`FROM`、`PREV` 等游戏允许的作用域。`political_*` 的国家和省份参数接受相应类型的 `ROOT`、`THIS`、`FROM`、`PREV`。在框架直接执行的块里，`instance = INSTANCE` 表示当前实例。由游戏延迟触发、另行打开的事件请用实际实例 ID，或使用只匹配一个活动实例的 `type`。

## 改革、诏令和事变

- 改革用 `on_effect` 处理通过时的一次性效果，`off_effect` 处理撤销。现有 `effect` 仍可用于通过时的效果。旧写法中单条 `add_prestige` 保留给发起国的历史行为。正常提交会重查条件和费用。脚本直接 `political_set_reform` 写入通过状态时不扣费，也不重放通过效果。
- 诏令用 `duration` 或 `duration_days` 指定天数。`effect` 在通过时运行，`removed_effect` 在到期时处理。到期记录写入存档，已清理的效果不会重放。普通决定和诏令也可以使用游戏的复合效果与 scripted effect。
- `modifier` 施加给配置的受益方，`emperor` 施加给现任领袖，`member` 施加给当前成员，`province` 施加给实例领土。受益方的变化走游戏的原生修正重算。联盟领土应在历史或政治脚本中声明。
- `ai_will_do` 的 `factor` 和条件修正走原版权重求值。何时尝试行动、从哪些行动中选择仍由框架的 AI 规则决定。
- 事变可以写开始 `effect`、终止条件 `can_stop` 和各选项的 `trigger`、`effect`。可在效果里调用普通的 `country_event`。原版神罗用 `event`、`default_option` 和编号权重定义投票流程，这套专属流程尚未移植到自定义实例。
- 新资源修正可在 `common/political_modifiers` 注册，并从国家或省份原版修正总值读取。验收包演示用普通 `add_country_modifier` 加上一个修正，使领袖所在联盟的月变从 `+2.00` 变为 `+3.00`。

## 原版依据

以下地址是 Windows Steam 1.37.5 的模块相对地址。原版脚本文件只供对照。

| 原版内容 | 二进制调用证据 |
| --- | --- |
| `common/imperial_reforms/00_hre.txt`、`00_hre_emperor.txt`、`01_china.txt` 按帝国区分改革，分开一次性效果和持续修正 | 启动读取 `0x20D6F2 → 0x801500`。改革字段分发 `0x800000` |
| `common/imperial_incidents/00_imperial_incidents.txt` 引用事件，设定结束判断、默认选项和编号权重 | `0x20D871 → 0x70F110`。原版事变对象构造 `0x710320` |
| `common/decrees/00_china.txt` 包括资格、费用、持续时间、修正、开始与撤销效果、AI 权重 | `0x20D9F0 → 0x479860`。原版字段分发 `0x4787F0` |
| 同一原版解析和执行路径 | `0x170DD70` 构造可分词的文本读取器，`0x170ADA0` 读取赋值，`0x17068B0` 分发脚本块。条件 `0xB98200`，复合效果 `0x5ED800`，权重 `0x8BE7B0` |
| 按实际国家与省份汇总修正 | 国家 `0x934030`，省份 `0x95D130`，合并 `0x8EA420`。国家重算 `0x327DC0`，省份重算 `0x9F9500` |
| 原版嵌套目标 | `0x5ED8A2`、`0x5ED8E9`、`0x5ED904` 分别使用 `ROOT`、`PREV`、`FROM` 的记录 |

离线编辑器可检查文件、布局、框架字段和花括号结构。对交给游戏读取的块，会给出行号及进游戏验证的提示。游戏读取时的报错会映射回作者文件和行号。当前包的战役验证仍待执行，游戏原版悬停框中是否逐条列出自定义修正来源也待核对。
